Basic design of how previous code worked, and problems
  * Call unpack_trees (which updates as it goes), then "fix it up"
  * unpack_trees unaware of renames, so "would be overwritten" has both
    false positives and false negatives
  * four-way-merge
  * considerations of multiple issues added to each conflict path
    * D/F conflicts
    * dirty and untracked contents
    * casename sensitivty
    * sparse entries
    * submodule handling

Stuff to include:
  * Create tree, then pass it to checkout machinery
    * Nukes all working-tree related code in merge machinery (shotgun blast)
    * Puts consideration for multiple issues into one place:
  * Why skip unpack_trees()
    * callbacks don't get enough information (masks)
    * can't avoid traversing into subtrees
    * a lot of irrelevant comparing to and updating of index
    * allows me to avoid strcmp and just do pointer comparisons of filenames
  * Perf restructures

  * API splitting; now three calls instead of one.
