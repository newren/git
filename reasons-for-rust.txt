We are getting killed in performance:
  * gitoxide can clone git repositories 3-4 times faster than git
    (https://github.com/Byron/gitoxide/discussions/579)
  * jj can run circles around git in rebasing time
    (https://github.com/martinvonz/jj/discussions/49)
  * I spent a few years of my life rewriting and optimizing the merge
    machinery and getting that all upstreamed.  I tried to leave no
    potential optimization opportunity uncovered -- with the exception
    of a glaring one: parallelization.  I didn't feel remotely
    confident about being able to parallelize that optimized C code in
    a reasonable amount of time; a language like Rust provides the
    necessary checks to give me confidence to fix that glaring
    omission.

* unittests

* avoid annoying platform-dependent issues (such as 72b3091040
  ("merge-ort: use STABLE_QSORT instead of QSORT where required",
  2021-03-20)

* reduction in types of security vulnerabilities
  (https://litchipi.github.io/infosec/2023/01/24/git-code-audit-viewed-as-rust-programmer.html#rusts-protection)


Methodology:
  * "surgically replace [some] parts [of Git] but keep most of the
    project intact."
    (https://unhandledexpression.com/rust/2017/07/10/why-you-should-actually-rewrite-it-in-rust.html)
